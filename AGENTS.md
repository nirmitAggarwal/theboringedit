# AGENTS.md — how to write for The Boring Edit

You are writing content for **The Boring Edit** — a static, markdown-compiled
blog. This file is the entry point. Read it, follow the one rule, and you will
not need to open random source files.

> **THE ONE RULE:** `content/posts/*.md` and `content/tracks/*.md` are the
> *only* source of truth for content. Everything else is generated or
> machinery. You will only ever *create or edit* files in `content/` and
> `public/images/` — never `src/`, never `scripts/`, never anything under
> `src/generated/` (it is auto-generated and says so at the top).

## The 60-second tour (all you usually need)

**Writing a post, end to end:**

1. Read `.agents/skills/write-post/SKILL.md` (+ the mode skill if one was named).
2. Create `content/posts/<slug>.md` — frontmatter block, then body. Full
   frontmatter reference and body syntax live in the skill and in the
   "Writing posts" section of `README.md`.
3. If it belongs to a series: add `track: <slug>` + `trackIndex: <n>` (the
   write-track skill explains numbering etiquette).
4. If it uses images: create SVGs in `public/images/` (style template is in
   the write-post skill) and reference them as `/images/<name>.svg`.
5. Validate: `npm run content:build` — must finish with **zero warnings**.
   Warnings are the build talking to you; fix what they point at.
6. Report to the user: file created, slug/URL, track part, reading time, and
   any image files you added.

**Never do these:**

- Never edit `src/generated/content.ts`, `public/sitemap.xml`, `robots.txt`,
  `feed.xml`, or `public/og/*.png` — all regenerated by the build.
- Never run `npm run build` or `npm run preview` unless asked —
  `content:build` is the content-level check.
- Never invent frontmatter keys. The full legal set is in the write-post skill.
- Never leave `excerpt: ""` — either write one (≤ ~160 chars, it becomes the
  meta description) or delete the key so one is auto-generated.
- Never reference an image that doesn't exist under `public/images/` — the
  build warns, and a missing figure ships broken.

**Environment notes:** Windows machine, bash shell — POSIX syntax, forward
slashes. `npm run content:build` takes ~25 s; that is normal, don't retry it.

## Where things actually live (only look here if the skills don't answer it)

```
content/posts/*.md          ← posts (source of truth)         ✏️ you edit
content/tracks/<slug>.md    ← track definitions                ✏️ you edit
public/images/*.svg         ← post artwork                     ✏️ you edit
scripts/build-content.ts    ← the compiler: frontmatter parsing, track
                              validation, warnings              👀 reference
scripts/markdown.ts         ← exact markdown features: math delimiters, code
                              fence meta, figure syntax          👀 reference
scripts/new-post.ts         ← scaffolder (npm run new:post)     👀 reference
scripts/config.ts           ← site name/author/URL              👀 reference
src/lib/types.ts            ← Post/Track TypeScript shapes      👀 reference
README.md                   ← human-facing docs; "Writing posts" and "Tracks"
                              sections mirror the skills in more depth
```

## Definition of done

A content task is finished when **all** of these hold:

1. `npm run content:build` exits 0 with **no ⚠ warnings**.
2. `npm run typecheck` passes (only matters if `src/generated/` changed,
   which it will have).
3. The post follows one named writing mode (or the write-post default voice)
   consistently from title to quest/footer.
4. Every link resolves: `/blog/<slug>` and `/tracks/<slug>` point at posts
   and tracks that exist; images exist under `public/images/`.
5. You reported what you made: path, slug, title, track/index if any, word
   count / reading time, images added, and the build result.
